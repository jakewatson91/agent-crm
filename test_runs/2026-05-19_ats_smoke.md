## Architecture notes

- Discovery is lazy + per-entity. First encounter probes each allowed provider × each slug variant; result cached on `entity.attributes.ats = { provider, slug, discovered_at }`. Negative results cached as `provider: 'none'` and re-probed after `reprobe_days` (default 30).
- Steady state: each cron tick fetches one endpoint per entity-with-known-provider. ~1424 * 0.5 = ~700 endpoint calls per run for a fully-discovered workspace. All free.
- Diff against `entity.attributes.ats_seen_jobs[]` — only NEW job IDs produce signals. Existing roles get added to the seen set silently.
- Failed fetches on known slugs (company removed board, changed slug) clear the hint so next run re-probes.

## Setup notes for forkers

This connector requires **zero configuration** beyond enabling it:

1. Insert a row in `sources` with `connector_type: 'ats'`. No config object needed — defaults to all 4 providers, daily cron.
2. Run the cron (or trigger manually). First few runs progressively discover ATS providers per entity; signals start landing immediately for entities with positive hits.
3. Optional tuning via config:
   - `providers`: narrow to a subset (`['greenhouse', 'lever']`)
   - `reprobe_days`: how often to re-check entities marked as having no ATS (default 30)
   - `max_entities_per_run`: cap per cron tick (default 200)

No API keys, no rate-limit concerns at default cadence, no LLM cost.
